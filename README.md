## 平台简介

- 本仓库为前端技术栈 [Vue3](https://v3.cn.vuejs.org) + [TS](https://www.typescriptlang.org/) + [Element Plus](https://element-plus.org/zh-CN) + [Vite](https://cn.vitejs.dev) 版本。
- 成员项目: 基于 vben(ant-design-vue) 的前端项目 [ruoyi-plus-vben](https://gitee.com/dapppp/ruoyi-plus-vben)
- 成员项目: 基于 vben5(ant-design-vue) 的前端项目 [ruoyi-plus-vben5](https://gitee.com/dapppp/ruoyi-plus-vben5)
- 配套后端代码仓库地址
- [RuoYi-Vue-Plus 5.X(注意版本号)](https://gitee.com/dromara/RuoYi-Vue-Plus)
- [RuoYi-Cloud-Plus 2.X(注意版本号)](https://gitee.com/dromara/RuoYi-Cloud-Plus)

## 前端运行

```bash
# 克隆项目
git clone https://gitee.com/JavaLionLi/plus-ui.git

# 安装依赖
npm install --registry=https://registry.npmmirror.com

# 启动服务
npm run dev

# 构建生产环境
npm run build:prod

# 前端访问地址 http://localhost:80
```

# 太行VisionAI前端

## 项目概述

太行VisionAI前端是一个基于Vue3的前端应用，用于展示和管理视频监控系统的各项数据。本项目包含系统信息展示、负载监控、资源信息统计等功能。

## 视频监控模块

### 功能列表

1. **设备管理**
   - 设备信息查看与编辑
   - 设备状态监控
   - 设备配置管理
   - 设备分组管理

2. **通道管理**
   - 通道信息查看与编辑
   - 通道列表展示
   - 通道状态监控
   - 通道视频直播预览

3. **系统控制台**
   - 系统资源使用情况
   - 设备、通道统计信息
   - 负载均衡状态
   - 系统性能监控

### 使用指南

1. **访问视频监控模块**
   - 在系统侧边栏中点击"视频监控"菜单
   - 选择需要进入的功能页面（设备管理、通道管理或系统控制台）

2. **设备管理**
   - 查看设备列表：显示所有注册的设备及其状态
   - 添加设备：点击"添加"按钮，填写设备信息
   - 编辑设备：点击设备行的"编辑"按钮
   - 删除设备：点击设备行的"删除"按钮
   - 刷新设备状态：点击"刷新"按钮

3. **通道管理**
   - 查看通道列表：显示所有注册的通道及其状态
   - 添加通道：点击"添加"按钮，填写通道信息
   - 编辑通道：点击通道行的"编辑"按钮
   - 删除通道：点击通道行的"删除"按钮
   - 观看通道视频：点击"播放"按钮

4. **系统控制台**
   - 查看系统实时数据
   - 监控系统资源使用情况
   - 查看设备和通道的统计信息

## 数据可视化界面更新

我们对数据控制台的可视化界面进行了全面升级：

### 1. 资源信息展示优化

- 采用圆形进度条直观展示各类资源的在线率
- 清晰的色彩区分：
  - 蓝色环形进度条（#1890ff）：表示100%在线的资源（设备、通道）
  - 灰色环形进度条（#E5E7EB）：表示0%在线的资源（推流、拉流代理）

  - 在圆环中央清晰显示百分比数值（100%或0%）
  - 使用适当字体大小和颜色，确保数据可读性
- 资源信息卡片布局：
  - 上方显示在线率百分比
  - 下方显示总数和在线数量
  - 整齐的网格布局，提升界面美观度

### 3. 中文界面优化

  - 图表标题、轴标签

- 采用符合中文阅读习惯的字体和排版

### 4. 响应式布局改进

## API连接机制改进

我们对API调用机制进行了全面重构，提高了系统的鲁棒性和可靠性：

### 1. 多路径尝试机制

- 实现了`tryMultipleApiPaths`函数，可以按顺序尝试多个可能的API路径
- 自动记忆成功的API路径，下次优先使用
- 支持的API路径格式包括:
  - 带前缀: `/api/server/system/info`
  - 无前缀: `/server/system/info`
  - 简化路径: `/system/info`

### 2. 简化的API调用

- 不再需要认证和登录，直接访问API
- 简洁的请求配置，提高代码可读性
- 自动添加时间戳参数，减少缓存影响

### 3. 数据处理增强

- 增强了系统信息、负载信息和资源信息的数据处理
- 支持多种返回数据格式:
  - 标准格式: `{code: 0, data: {...}}`
  - 直接对象: `{...}`
  - 非零状态下的有效数据: `{code: 1, data: {...}}`
- 详细的日志记录，便于调试和故障排除

### 4. 重试和降级机制

- 实现了API调用失败的重试机制
- 当重试达到上限后自动回退到模拟数据
- 定时器自适应暂停和恢复
- 智能错误处理和日志记录

## API配置

项目支持多种API配置方式:

1. **基础URL配置**:
   - 默认使用 `http://localhost:18080`
   - 可通过localStorage中的`api_base_url`项修改

2. **数据刷新间隔**:
   - 系统信息: 5秒
   - 负载和资源信息: 10秒

## 主要功能

- **系统信息展示**: CPU、内存、网络和磁盘使用情况
- **负载监控**: 节点负载情况
- **资源信息**: 设备、通道、推流和代理的总数和在线数

## 故障排除

遇到API连接问题时:

1. 检查浏览器控制台日志
2. 验证API服务是否正常运行
3. 确认API基础URL是否正确
4. 检查是否存在跨域问题

API连接错误类型:
- 404: API路径不正确，检查URL配置
- 500: 服务器内部错误，联系后端开发人员
- 超时: 网络问题或服务器负载过高

## 前后端API规范

前后端通信遵循以下规范:

1. 使用JSON格式进行数据交换
2. API响应标准格式: `{code: 0, data: ...}`
3. 无需认证，直接访问API
4. 错误处理: 返回标准错误码和错误信息

- `api_base_url`: API服务器基础URL
- `wvp_*_path`: 各API端点的成功路径
